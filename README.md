## 项目简介

这个项目的目标不是把整篇论文直接丢给大模型“问一句”，而是先把论文拆成更适合模型理解和定位的问题结构，再结合系统默认规则与用户自定义规则，生成更细粒度、更可追踪的审稿意见。

它重点解决以下问题：

- 论文篇幅长，直接投喂大模型成本高、稳定性差
- 审稿意见容易空泛，缺少明确位置、原文证据和修改建议
- 导师、学院、答辩小组经常有自己的审查要求，需要叠加到统一流程里
- 图表、章节、段落之间的对应关系，传统摘要式问答很难处理好

因此，这个项目采用了“解析优先、结构化优先、定位优先”的设计思路。

## 核心能力

- 上传 `docx` / `pdf` 毕业论文
- 自动从标题页识别论文标题，也支持手动修改标题
- 自动解析章节、节、小节、段落结构
- 单独抽取表格、图片及其上下文信息
- 对图片内容做独立理解；未配置视觉模型时可自动跳过
- 支持学院要求、导师关注点等自定义规则集
- 支持系统默认规则人工勾选，并与自定义规则叠加
- 调用兼容 OpenAI 风格接口的平台进行快速审稿 / 深度审稿
- 支持接入百炼兼容接口、DeepSeek、Ollama / 本地兼容网关
- 输出总分、分项分数、分章问题、原文证据、修改建议
- 支持“论文内容 - 审稿意见”对应查看
- 支持 Markdown / PDF 审稿报告导出
- 支持 Word 批注版论文导出
- 支持任务状态追踪、失败定位、日志调试、任务删除与历史任务保留

## 使用流程

```text
上传论文
  -> 文档解析
  -> 章节 / 段落 / 表格 / 图片结构化存储
  -> 标题页标题识别（支持手动修正）
  -> 叠加系统默认规则与用户规则
  -> 视觉模型图片理解（可跳过）
  -> 文本模型分章节审稿
  -> 文本模型总评汇总与评分
  -> 页面查看 / Markdown / PDF / Word 导出
```

## 页面能力

### 1. 页面结构

- 页面顶部分为标题区和统计区
- 主界面分为两个标签页：
  - `论文审核`
  - `历史任务`
- 设置入口为主标签栏右侧齿轮按钮，采用悬浮弹窗形式

### 2. 论文审核页

- 页面中部提供大尺寸拖拽上传区
- 默认论文类型为 `本科`
- 默认审稿模式为 `快速审稿`
- 支持点击选择文件，也支持拖拽上传
- 当前支持 `docx` 与非扫描版 `pdf`
- 上传后页面下方展示当前任务的审核进度、解析统计、规则选择和报告摘要
- 顶部工具栏支持：
  - 编辑标题
  - 重新解析
  - 开始审稿
  - 删除任务
  - 导出

### 3. 历史任务页

- 左侧展示历史任务卡片
- 右侧展示当前任务详情
- 提供四个详情标签页：
  - `总览`
  - `解析视图`
  - `审稿报告`
  - `论文与意见对应`

### 4. 规则管理

- 上传规则文件或直接粘贴规则文本
- 保存为可复用规则集
- 查看已有规则
- 启用 / 停用 / 删除规则
- 审稿时可单独勾选系统规则
- 审稿时可叠加启用的自定义规则

### 5. 设置弹窗

- `界面外观`
  - 切换主题背景
- `规则管理`
  - 新增、启用、停用、删除规则集
- `LLM 设置`
  - 配置兼容 OpenAI 风格的接口地址
  - 配置 API Key
  - 配置文本模型、温度、最大输出长度
- `图片模型设置`
  - 配置视觉模型、图片理解输出长度、图片理解数量上限
  - 若当前服务商不提供视觉模型，可将视觉模型留空，系统会跳过图片理解，仅基于正文、表格与已有图题继续审稿
- `导出内容`
  - 配置导出模块开关

### 6. 审稿结果

- 总评结论
- 四项评分与总分
- 分章具体意见
- 论文与意见对应查看
- Markdown / PDF / Word 批注版导出

## 审稿输出内容

系统会尽量从以下维度给出结果：

- 论文主要内容概括
- 各章设置是否合理
- 各节叙述逻辑是否顺畅
- 标题与内容是否匹配
- 技术动机、合理性与论证完整性
- 章与章、节与节、段与段之间是否连贯
- 实验 / 测试 / 仿真是否足以支撑结论
- 整体工作量是否达标
- 总分与各维度分项评分
- 对于硕士论文，提炼创新点并评估创新点与章节对应关系

当前评分结构为：

- `创新意识`：30 分
- `实现质量`：30 分
- `撰写质量`：20 分
- `逻辑结构`：20 分
- 总分 `100` 分，`70` 分以下判定为不合格

问题项会尽量附带：

- 问题标题
- 严重程度
- 问题类型
- 位置标签
- 原文证据
- 问题分析
- 修改建议
- 润色建议

## 技术栈

### 后端

- `FastAPI`
- 本地 JSON 持久化
- 异步任务调度
- `httpx` 调用兼容 OpenAI 风格的接口

### 文档解析

- `python-docx` 解析 Word
- `PyMuPDF` 解析 PDF 与图片
- `pdfplumber` 提取表格

### 前端

- 原生 HTML / CSS / JavaScript
- 单页式本地工作台界面

### 审稿输出

- 分章节结构化输出
- 总评汇总结构化输出
- 四项分数与总分输出
- Word 批注版导出

## 本地启动

### 1. 安装依赖

```bash
uv run --python 3.12.13 python -m pip install -r requirements.txt --target .deps
```

### 2. 启动服务

```bash
./run.sh
```

等价命令：

```bash
PYTHONPATH=.deps uv run --python 3.12.13 python -m uvicorn app:app --host 127.0.0.1 --port 8000 --reload
```

### 3. 打开浏览器

```text
http://127.0.0.1:8000
```

### 4. Python 版本注意事项

安装 `.deps` 和启动服务时，必须使用同一个 Python 版本。  
如果 `.deps` 是用 Python `3.10` 装出来的，却用 Python `3.12` 启动，就可能出现 `pydantic_core` 之类的二进制兼容错误。

如果遇到这类问题，可以这样重新安装：

```bash
rm -rf .deps
uv run --python 3.12.13 python -m pip install -r requirements.txt --target .deps
./run.sh
```

## 接口配置建议

建议在设置弹窗中填写：

- 接口地址：
  - `https://dashscope.aliyuncs.com/compatible-mode/v1`
  - 或 `https://api.deepseek.com`
  - 或 `http://127.0.0.1:11434/v1`
- API Key
- 文本模型：
  - 例如 `qwen-plus`
  - 或 `deepseek-chat`
  - 或 `gemma4:e4b`
- 视觉模型：
  - 例如 `qwen-vl-max`
  - 若使用 DeepSeek 且当前无视觉模型，可留空
  - 若使用本地 Ollama 且当前模型不支持多模态，也可留空
- 文本输出上限：
  - 建议从 `4096` 或 `8192` 开始
- 图片输出上限：
  - 建议从 `512` 或 `1024` 开始
- 图片理解数量上限：
  - 调试阶段建议先设置为 `5` 或 `8`

当前版本会在终端输出比较详细的过程日志，便于判断到底卡在哪一步。

你可以看到：

如果模型确实有返回，终端会出现类似：


## 当前限制

- 当前仅支持非扫描版 PDF，不做 OCR
- PDF 的复杂跨页表格、复杂图文排版仍可能需要人工复核
- 论文结构切分依赖标题样式、编号和文本块推断，极端排版下可能误判
- 图片较多时，视觉模型调用会明显增加总耗时
- 当前是本地单用户版本，不包含多账号和线上部署能力
